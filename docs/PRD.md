## 1. 서비스 개요

### 1.1 배경 및 문제 정의

**시장 배경**
- 국내 상업 웹툰 플랫폼(네이버, 카카오)은 작가 정산율이 낮고(통상 30~50%), 노출 우선순위가 알고리즘과 광고 예산에 종속됨.
- 포스타입, 딜리헙 등 직영형 플랫폼이 존재하나, 작가별 브랜드/팬덤 구축에는 여전히 제약이 있음(공통 UI, 작가 페이지의 커스터마이즈 한계, 플랫폼 수수료).
- 1인 작가의 경우 **자기 도메인 + 직접 결제 + 팬 직접 소통** 채널 부재로 인해, SNS(트위터/인스타) 팔로워를 실 매출로 전환하지 못함.

**해결하려는 문제**
1. 작가 직영 채널 부재 → 수수료 손실, 팬 이탈, 정산 지연.
2. 팬 소통의 분절(SNS/Discord/플랫폼 댓글이 따로) → 팬덤 결속력 약화.
3. 신뢰성 있는 결제·뷰어 인프라를 1인 작가가 직접 구축하기 어려움 → "내 사이트"를 가지고 싶어도 못 만듦.

**서비스 정의**
- 1인 웹툰 작가가 자기 작품을 직접 판매·연재·소통할 수 있는 개인 플랫폼.
- 핵심 가치: **작가 100% 수익화(포트원 수수료 외 0%) + 직접 팬 소통 + 모바일 친화 뷰어**.

### 1.2 목표 및 성공 지표 (KPI)

**비즈니스 목표 (런칭 후 12개월)**
| 지표 | 목표 | 비고 |
|------|------|------|
| 누적 가입자 | 5,000명 | 작가 SNS 팔로워 기반 유입 |
| MAU (월 활성 사용자) | 1,000명 | 6개월 차 기준 |
| 결제 전환율 (가입자→첫 구매) | 20% 이상 | 무료 N화 → 유료 전환 |
| 객단가 (1회 결제 평균) | 2,500원 (5화 구매 가정) | 에피소드 단가 500원 |

| 댓글/하트 참여율 (구매자 대비) | 30% 이상 | 커뮤니티 활성도 |

## 2. 사용자 정의

### 2.1 페르소나

#### 페르소나 A: 신규 독자 "민지" (24세, 대학생)
- **유입 경로**: 작가의 X(트위터) 게시물 → 미리보기 컷 → 사이트 방문
- **디바이스**: 모바일 (iOS Safari) 95%, PC 5%
- **목표**: 작품을 한번 훑어보고 마음에 들면 결제
- **고민/장벽**:
  - 개인 사이트라 결제가 안전한지 불안 → 카카오페이/토스 선호
  - 회원가입이 귀찮음 → 소셜 로그인 필수
  - 미리보기 없으면 이탈
- **핵심 행동**: 무료 1~3화 열람 → 가입 → 카카오페이 결제 → 다음 화

#### 페르소나 B: 충성 팬 "수현" (32세, 직장인)
- **유입 경로**: 새 에피소드 푸시/이메일 알림
- **디바이스**: 모바일(주) + PC(주말)
- **목표**: 새 회차 빠르게 열람 + 작가에게 반응 남기기
- **고민/장벽**:
  - 매번 결제 흐름이 번거로움 → 전편 구매/묶음 결제 선호
  - 댓글이 묻히면 작가 반응 못 받음 → 하트/댓글 알림
- **핵심 행동**: 알림 클릭 → 결제 → 즉시 열람 → 댓글 + 후원

#### 페르소나 C: 커뮤니티 활성 유저 "재은" (28세, 프리랜서)
- **유입 경로**: 즐겨찾기 직접 방문
- **디바이스**: PC 60%, 모바일 40%
- **목표**: 작가의 근황·Q&A·투표에 참여, 다른 팬과 교류
- **고민/장벽**:
  - 댓글 답글 알림이 없으면 대화 흐름 놓침
  - 작가 답변이 따로 표시되지 않으면 묻힘
- **핵심 행동**: 근황 게시판 → 댓글/답글 → 투표 참여 → 후원

### 2.2 사용자 여정 (User Journey)

#### 여정 1: 신규 유입 → 첫 결제 (페르소나 A)
```
[인지]    SNS에서 작가 미리보기 봄
   ↓
[방문]    링크 클릭 → 작품 상세 페이지
   ↓
[탐색]    1~3화 무료 열람 (게스트 상태)
   ↓
[전환 트리거] 4화 진입 시 "로그인 필요" 모달
   ↓
[가입]    카카오 OAuth 1초 가입
   ↓
[결제]    4화 구매 (500원) → 카카오페이 → 즉시 열람
   ↓
[재방문]  알림 수신 동의 → 다음 화 업로드 시 푸시
```

#### 여정 2: 충성 팬 재방문 → 묶음 결제 (페르소나 B)
```
[알림 수신] "새 에피소드가 올라왔어요" 메일/푸시
   ↓
[방문]      알림 → 에피소드 페이지 (자동 로그인)
   ↓
[결제]      이미 결제 수단 저장 → 1탭 결제
   ↓
[열람]      세로 스크롤 뷰어
   ↓
[참여]      ❤️ 하트 + 댓글 작성
   ↓
[후원]      특히 좋았던 회차 → 후원 (1,000원~)
```

#### 여정 3: 커뮤니티 참여 (페르소나 C)
```
[방문]      즐겨찾기 직접 진입
   ↓
[탐색]      커뮤니티 게시판 (근황 / Q&A / 투표)
   ↓
[참여]      투표 참여 + Q&A 작성
   ↓
[알림]      작가 답글 알림 수신
   ↓
[재방문]    답글 확인 → 추가 댓글
```

## 3. 기능 요구사항

> **우선순위 정의**
> - **P0** (런칭 필수, MVP): 이 기능 없이는 서비스 출시 불가
> - **P1** (런칭 후 4주 내 추가): 매출/유지율 직접 영향
> - **P2** (안정화 후 추가): 부가 가치, 시장 검증 후 진행

| ADM-05 | 수익 대시보드 | 일/주/월 매출, 작품별·에피소드별 매출, 결제 수단별 매출. | P0 |
| ADM-06 | 독자 통계 | 가입자 추이, MAU, 회차별 열람 수, 결제 전환율. | P1 |
| ADM-07 | 댓글/신고 관리 | 신고된 댓글 리스트 + 삭제/유지 처리. | P1 |
| ADM-08 | 환불 처리 | 환불 요청 리스트 + 승인/거부. PAY-06과 연계. | P0 |
| ADM-09 | 업로드 리마인더 | 마지막 업로드 후 N일 경과 시 작가에게 이메일. | P2 |
| ADM-10 | 후원 메시지 확인 | 후원 내역 + 메시지 표시. | P1 |
| ADM-11 | 커뮤니티 게시글 작성 | 근황/투표 게시글 작성 (작가 = 관리자). | P1 |

> **권한(role) 분리 (3-역할 RBAC, DECISIONS "관리자 권한 분리")**: 위 ADM 기능은 전부 **Owner(작가)** 권한이다(`require_owner`). **Moderator**(운영자)는 게시글 삭제·문의 답변(ADM-07류)만 갖고 매출·콘텐츠는 차단 - M4에서 owner가 부여(`require_role(OWNER, MODERATOR)`). authz는 DB `user.role` 기준. **개발자는 product 역할이 아니다**(관측은 외부 도구 Sentry 등). "개발자가 매출을 못 본다"는 라우트 가드가 아니라 인프라/자격증명 소유권으로 친다(진짜 장벽 M7, 상세 DECISIONS).

### 3.2 비기능 요구사항

#### 성능
- 페이지 응답
  - 첫 페이지 (`/`, `/works`): LCP < 2.5초 (모바일 3G fast 기준).
  - 뷰어: 첫 이미지 표시 < 1.5초. 나머지 이미지도 **동시에** 요청되므로(lazy 아님 - DECISIONS "뷰어 이미지 로딩") 앞 2~3장에 `fetchpriority="high"`를 줘야 이 목표가 지켜진다 - 우선순위 없이는 대역폭 경쟁으로 첫 이미지가 오히려 늦어진다.
- API: 평균 < 500ms, p95 < 1초.
- 동시 접속: 100명 동시 뷰어 열람 지원 (Hetzner 2vCPU/4GB 기준 부하 테스트로 검증).

#### 보안
- 통신: 전 구간 HTTPS (Caddy + Let's Encrypt 자동).
- 인증: JWT는 **HttpOnly + Secure + SameSite=Lax 쿠키**에만 저장. localStorage 금지.
- 결제: 클라이언트 신뢰 금지. 모든 결제는 서버에서 포트원 REST로 재검증.
- 콘텐츠: 미결제 유저에게 이미지 URL 절대 비공개. Signed URL **회차 단위 1개**, TTL 10분.
- CORS: 허용 도메인 화이트리스트 (`*` 금지).
- SQL: SQLModel ORM 사용. 원시 SQL 금지. (DB_GUIDE 참조)
- 환경변수: 코드 하드코딩 금지. `.env` + Pydantic Settings로 로드.
- Rate limiting: 로그인 5회/분, 결제 시도 10회/분, 댓글 10회/분.
- 비밀번호: bcrypt cost=12.
- 관리자: 2FA(TOTP) 필수. (IP 화이트리스트는 안정화 후 도입)

#### 확장성
- 컨테이너: 모든 서비스 Docker 이미지. docker-compose로 단일 호스트 운영.
- DB: PostgreSQL 단일 인스턴스(MVP). 백업: 일 1회 R2 덤프 업로드.
- 정적 자산: Cloudflare CDN.
- 이전 가능성: VPS 이전 시 docker-compose pull + volume 마운트로 1시간 내 복구.

#### 운영
- 로깅: 구조화 JSON 로그 → 파일. Sentry로 ERROR 이상 전송.
- 모니터링: UptimeRobot (5분 간격), Sentry (에러), Hetzner 콘솔 (리소스).
- 알림: 다운 감지 시 작가에게 카카오톡 알림 (UptimeRobot).
- 백업: PostgreSQL 일 1회 풀 덤프 → R2 30일 보관. 미디어는 R2 자체 버전 관리.

## 4. 화면 흐름 (Flow)

### Flow 1: 신규 가입 + 첫 결제
```
1. 사용자가 SNS 링크로 작품 상세 페이지(/works/123) 진입
2. "에피소드 목록"에서 1~3화 (무료) 클릭 → 뷰어 진입 (게스트)
3. 4화 클릭 → "로그인이 필요해요" 모달
4. [구글로 시작하기] 클릭 (MVP는 구글만 제공, 카카오는 P1)
5. 구글 OAuth → 동의 → 콜백 → 백엔드 토큰 검증 → JWT 쿠키 발급
6. 자동으로 이전 페이지(4화)로 리다이렉트
7. 4화는 유료 → "500원으로 구매하기" 버튼
8. 클릭 → 포트원 결제창 (카카오페이 기본)
9. 결제 완료 → 백엔드로 imp_uid 전송
10. 백엔드: 포트원 API로 금액 검증 → Purchase 레코드 생성
11. 응답에 Signed URL 포함 → 뷰어에 이미지 로드
12. 뷰어 하단 "구매해주셔서 감사합니다 ❤️" + 다음 화 결제 버튼
```

### Flow 2: 충성 팬 재방문
```
1. 이메일 알림 "새 에피소드가 올라왔어요" 수신
2. 링크 클릭 → 자동 로그인 (Refresh Token 유효) → 에피소드 페이지
3. "구매하기" 클릭 → 결제창 (이전 카드 정보 자동 입력)
4. 결제 완료 → 뷰어 진입
5. 스크롤 종료 후 ❤️ 하트 클릭
6. 댓글 작성 → 등록
7. "이 회차 후원하기" → 3,000원 후원 + 메시지
```

### Flow 3: 에피소드 업로드 (관리자)
```
1. 관리자가 admin.example.com 접속
2. 이메일·비번 + TOTP 입력 → 로그인
3. [작품 관리] → 해당 작품 선택 → [새 에피소드]
4. 회차 번호, 제목, 공개일시 입력
5. 이미지 드래그앤드롭 (10~50장)
6. 각 이미지 → R2 업로드 (presigned PUT) → DB에 페이지 레코드 생성
7. 순서 조정 (드래그)
8. [임시저장] 또는 [예약 공개] 선택
9. 예약 공개 시 → 스케줄러가 공개일시 도달 시 published=true 변경
10. 공개 시점에 알림 발송 (해당 작품 1회 이상 구매 유저 대상)
```

### Flow 4: 결제 실패 처리
```
1. 사용자가 결제 시도 → 카드사 거절
2. 포트원 결제창에서 실패 응답
3. 클라이언트: 백엔드에 imp_uid + fail 상태 전송
4. 백엔드: 포트원 조회 → 상태 confirm → 실패 로그 기록 (Sentry)
5. 사용자에게 "결제에 실패했습니다. 다른 수단으로 시도하시겠어요?" 모달
6. Purchase 레코드 생성하지 않음
7. 사용자가 [재시도] → 처음으로
```

### Flow 5: 환불
```
1. 사용자가 [구매 내역] → 회차 옆 [환불 요청] (7일 이내·미열람만 표시)
2. 환불 사유 선택 → 신청
3. 관리자 대시보드 [환불 요청] 탭에 노출
4. 관리자 [승인] → 백엔드: 포트원 cancel API 호출
5. 성공 → Purchase에 refunded_at 기록, 권한 회수
6. 사용자에게 "환불이 완료되었습니다" 메일
```

## 5. 제약 조건 및 가정

### 5.1 기술적 제약
- **인프라**: Hetzner 싱가포르 VPS (2vCPU/4GB). 동시 접속 한계 100명 가정. 초과 시 서울 리전(AWS Lightsail) 이전 검토.
- **DB**: PostgreSQL 단일 인스턴스. 읽기 복제본 없음. WAL 백업으로 RPO 1일.
- **결제**: 포트원 의존 - 포트원 장애 시 결제 전면 중단(대체 PG 없음). 가맹점 심사 1~2주 소요.
- **소셜 로그인**: 카카오·구글 디벨로퍼 콘솔 사전 등록 필요. 리다이렉트 URI 변경 시 양쪽 콘솔 수정.
- **R2**: 월 무료 트래픽 한도(10GB egress) 초과 시 과금. CDN 캐시 적중률 90% 이상 유지 필요.
- **이메일**: 자체 메일서버 운영 안 함. 외부 SMTP (예: SendGrid/Resend 무료 플랜 100/day) 사용.

### 5.2 일정 제약
- **MVP (P0) 목표**: 4개월 (인증 1개월 + 작품/뷰어 1개월 + 결제 1개월 + 관리자 + QA 1개월).
- **P1 추가**: 런칭 후 8주 내.
- **P2**: 시장 반응 보고 결정.

### 5.3 외부 의존성
| 의존성 | 용도 | 리스크 |
|--------|------|--------|
| 포트원 | 결제 | 가맹점 심사 지연, API 변경 |
| 카카오 OAuth | 로그인 | 정책 변경, 일 API 한도 |
| 구글 OAuth | 로그인 | 동의 화면 인증 필요(60일 내) |
| Cloudflare R2 | 이미지 저장/전송 | egress 초과 과금 |
| Hetzner | VPS | 싱가포르 → 한국 지연 |
| Let's Encrypt | HTTPS 인증서 | 자동화 실패 시 만료 위험 |
| Sentry | 에러 추적 | 무료 플랜 한도(이벤트 5K/월) |
| UptimeRobot | 모니터링 | 무료 플랜 50개 모니터 |

### 5.4 비즈니스 가정
- 작가는 주 1회 이상 에피소드 업로드 (재방문 트리거).
- 유저는 모바일 SNS 유입 위주.
- 무료 회차 정책은 작품별 1~5화 범위.
- 결제 단가 500원/회차, 전편 구매 시 10% 할인.
- 초기 트래픽은 SNS 의존, 검색 유입은 6개월 후 본격화 (그래서 Astro SSG).
- 1인 운영이므로 신고/환불/CS는 24~48시간 대응 가능.

  → **결정**: **구글 P0, 카카오 P1.** 구글은 클라이언트 ID만 발급하면 즉시 개발 가능. 카카오 비즈앱은 사업자 서류 필요해서 출시 결정 전까지 보류. → AUTH-03 매트릭스 + Flow 1 반영.
- **Q21** ✅ 커미션 페이지(COMM-13) P1 승격
  → **결정**: 작가가 출시 시점부터 의뢰 받을 계획 → **P1으로 승격**. → COMM-13 매트릭스 반영.
