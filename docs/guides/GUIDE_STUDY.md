# Study 가이드

study/는 매번 다시 찾지 않아도 되는 누적 자산이다.
한 번 정리하면 다음 세션에서 재사용된다 - 이 원칙이 모든 결정의 기준.

---

## 폴더 구조

```
study/
├── index.md          # 전체 개념 카탈로그 (항상 최신 유지)
├── concepts/         # 개념별 파일 (토픽 하나 = 파일 하나)
└── sessions/         # 세션별 기록 (날짜 기반)
```

---

## index.md

전체 concepts/ 목록과 한 줄 요약을 관리한다.
새 concepts/ 파일을 만들면 반드시 index.md에 추가.

```markdown
# Study Index

## 개념 목록
- [[pnpm-workspace]] - 모노레포 패키지 관리, workspace:* 참조 방식
- [[vite-peer-dependency]] - peer dep 버전 충돌과 해결
```

---

## concepts/ 파일

**언제 만드는가**
다음 세션에서도 다시 찾아볼 만한 독립적인 개념/기술. 일회성 트러블슈팅은 sessions/에만 기록하고 concepts/는 만들지 않는다.

**파일명**: `kebab-case.md` (영어, 소문자, 하이픈)

**포맷**:

```markdown
# 개념 이름

## 한 줄 정의

한 문장으로 무엇인지.

## 왜 쓰는가

이 프로젝트에서 어떤 문제를 해결하는가.

## 핵심 내용

코드 예제, 구조, 주요 명령어 등. 자유롭게 섹션 추가.

## 관련 개념

- [[관련-개념-1]] - 연결 이유 한 줄
- [[관련-개념-2]] - 연결 이유 한 줄
```

---

## sessions/ 파일

**언제 만드는가**
의미 있는 작업 세션 - 새 개념을 배웠거나, 디버깅 과정이 길었거나, 설계 결정이 있었던 경우.
단순 수정/정리 세션은 생략 가능.

**파일명**: `YYYY-MM-DD-주제.md` (주제는 한글 가능)

**포맷**:

```markdown
# YYYY-MM-DD - 주제

## 이 세션에서 한 것

- (bullet로 요약)

## (섹션들 - 명령어, 코드, 디버깅 과정 등 자유롭게)

---

## 개념 정리

- [[개념-1]]
- [[개념-2]]
```

sessions/의 "개념 정리" 섹션은 이 세션에서 다룬 concepts/ 파일을 연결하는 용도.

---

## [[wiki-link]] 컨벤션

- `[[파일명]]` 형식, `.md` 생략, kebab-case
- concepts/ 파일 간, sessions/에서 concepts/ 참조 모두 동일 형식
- 아직 없는 개념을 링크해도 됨 - 나중에 만들 것을 표시하는 용도

---

## 세션 종료 시 체크

1. 새로 배운 독립 개념 있으면 concepts/ 파일 생성 + index.md 업데이트
2. 의미 있는 세션이면 sessions/ 파일 작성
3. 고아 링크 확인: sessions/에서 참조한 [[개념]]이 concepts/에 없으면 만들거나 링크 제거

## 학습 퀴즈 규칙 (active recall)

study는 적기만 하면 수동적 입력이라 기억에 안 남는다(적어둔 개념을 정작 본인이 모르는 사고가 실제로 있었다). 능동적 회상(스스로 답하기)으로 정착시킨다. 아래는 Claude가 지켜야 할 규칙이며, `.claude/hooks/study-quiz.py`(저장 시)와 `study-review.py`(세션 시작 시)가 트리거 리마인더를 주입한다. **주관식 채점은 셸로 불가능하므로 출제·채점은 Claude가 수행한다.**

### 1. 저장 직후 퀴즈 (concepts 한정)

`study/concepts/`에 개념 파일을 새로 쓰거나 의미있게 보강하면, **다른 작업으로 넘어가기 전에** 방금 저장한 개념으로 퀴즈를 낸다.
- **객관식 1개 이상** (`AskUserQuestion`) + **주관식 1개 이상** (평문 질문, 사용자가 직접 서술).
- 사소한 수정(오타, 위키링크, 포맷)은 생략.

### 2. 일일 복습 (spaced retrieval)

세션 시작 시 `study-review.py` 훅이 복습 로그를 읽어 **오늘 복습이 도래한 개념 중 우선순위가 가장 높은 1개만 지목**한다. 우선순위 = ①직전 결과가 fail인 개념(복습 backlog) ②그다음 밀린 순. Claude는 지목된 개념으로 객관식 1 + 주관식 1의 복습 퀴즈를 낸다(첫 작업 직전 등 적절한 시점). 훅이 "도래한 개념 없음/오늘 복습 이미 선점됨"이라고 하면 복습을 생략한다. 사용량을 제한하기 위해 세션 수와 관계없이 하루 전체 복습은 1개이며, 시간이 지난 뒤의 인출을 위한 이 복습은 저장 직후 퀴즈와 별개로 둔다.

**세션 dedup**: 훅은 날짜 단위 원자적 선점 파일(`study/.review-claim-<날짜>`, O_EXCL)로 오늘의 복습 여부를 기록한다. 먼저 시작한 세션만 한 개념을 맡고 같은 날의 후속 세션은 추가 복습을 내지 않는다. 선점 파일은 다음 날 훅이 자동 정리한다.

> 개념 선택을 Claude 재량("오래된 것 우선")에 맡기지 않는 이유: 복습 이력이 없으면 매 세션의 Claude가 같은 논리로 같은 개념을 고른다(2026-07 초 일주일간 pnpm-workspace만 반복 출제된 사고). 선택은 훅이 로그 기반으로 결정론적으로 수행한다.

### 3. 채점 & 진행

- 핵심 이해를 확인하면 진행.
- **틀리면: 왜 틀렸는지 설명 → 재질문.** 사용자가 핵심을 맞힐 때까지 반복하되, 무한루프 방지를 위해 핵심 한 가지가 확인되면 통과로 본다.
- 주관식은 표현이 달라도 **핵심 개념이 맞으면 정답** 처리(관대하게 채점하되 틀린 부분은 짚어줌).
- **학습이 구현보다 우선** - 퀴즈를 건너뛰고 코드부터 짜지 말 것.
- 재질문으로 결국 통과했더라도 **로그에는 첫 시도 결과를 기록**한다(아래 4번 - fail이면 다음날 재출제).

### 4. 복습 주기 & 로그 (말해보카식 SRS, 2026-07-10 도입)

망각곡선 기반 간격 반복: 맞춘 개념은 복습 간격을 점차 늘리고, 못 맞춘 개념은 다음날 다시 인출시킨다(막 잊기 시작하는 시점의 인출이 가장 효과적).

- **로그 파일**: `study/review-log.local` (gitignore 로컬 전용). 퀴즈 채점 직후 Claude가 TSV 한 줄 append:
  `복습일(YYYY-MM-DD) <TAB> 개념이름 <TAB> pass|fail <TAB> 연속정답수 <TAB> 다음복습일`
- **pass 기준**: 객관식·주관식 **모두 첫 시도에 핵심 정답**. 하나라도 재질문이 필요했으면 fail.
- **간격 사다리**: `[1, 4, 7, 14, 30, 60]`일. 다음복습일 = 오늘 + 사다리[min(연속정답수, 5)].
  - pass → 연속정답수 = 직전 + 1 (이력 없으면 1 → 4일 뒤)
  - fail → 연속정답수 = 0 → **다음날 재출제**
  - 새 개념 저장 직후 퀴즈(규칙 1) → 결과 무관 연속정답수 0, 다음복습일 +1일 (갓 배운 개념은 망각 급락 구간이라 1일 뒤 첫 인출)
- 복습 이력이 없는 기존 개념은 저장일 기준 오래된 것부터 백로그로 소화된다(훅이 자동 처리).
