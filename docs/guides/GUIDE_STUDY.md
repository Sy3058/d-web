# Study 가이드

study/는 매번 다시 찾지 않아도 되는 누적 자산이다.
한 번 정리하면 다음 세션에서 재사용된다 - 이 원칙이 모든 결정의 기준.

---

## 폴더 구조

```
study/
├── index.md          # 전체 개념 카탈로그 (항상 최신 유지)
├── concepts/         # 개념별 파일 (토픽 하나 = 파일 하나)
└── sessions/         # 세션별 기록 (날짜 기반)
```

---

## index.md

전체 concepts/ 목록과 한 줄 요약을 관리한다.
새 concepts/ 파일을 만들면 반드시 index.md에 추가.

```markdown
# Study Index

## 개념 목록
- [[pnpm-workspace]] - 모노레포 패키지 관리, workspace:* 참조 방식
- [[vite-peer-dependency]] - peer dep 버전 충돌과 해결
```

---

## concepts/ 파일

**언제 만드는가**
다음 세션에서도 다시 찾아볼 만한 독립적인 개념/기술. 일회성 트러블슈팅은 sessions/에만 기록하고 concepts/는 만들지 않는다.

**파일명**: `kebab-case.md` (영어, 소문자, 하이픈)

**포맷**:

```markdown
# 개념 이름

## 한 줄 정의

한 문장으로 무엇인지.

## 왜 쓰는가

이 프로젝트에서 어떤 문제를 해결하는가.

## 핵심 내용

코드 예제, 구조, 주요 명령어 등. 자유롭게 섹션 추가.

## 관련 개념

- [[관련-개념-1]] - 연결 이유 한 줄
- [[관련-개념-2]] - 연결 이유 한 줄
```

---

## sessions/ 파일

**언제 만드는가**
의미 있는 작업 세션 - 새 개념을 배웠거나, 디버깅 과정이 길었거나, 설계 결정이 있었던 경우.
단순 수정/정리 세션은 생략 가능.

**파일명**: `YYYY-MM-DD-주제.md` (주제는 한글 가능)

**포맷**:

```markdown
# YYYY-MM-DD - 주제

## 이 세션에서 한 것

- (bullet로 요약)

## (섹션들 - 명령어, 코드, 디버깅 과정 등 자유롭게)

---

## 개념 정리

- [[개념-1]]
- [[개념-2]]
```

sessions/의 "개념 정리" 섹션은 이 세션에서 다룬 concepts/ 파일을 연결하는 용도.

---

## [[wiki-link]] 컨벤션

- `[[파일명]]` 형식, `.md` 생략, kebab-case
- concepts/ 파일 간, sessions/에서 concepts/ 참조 모두 동일 형식
- 아직 없는 개념을 링크해도 됨 - 나중에 만들 것을 표시하는 용도

---

## 세션 종료 시 체크

1. 새로 배운 독립 개념 있으면 concepts/ 파일 생성 + index.md 업데이트
2. 의미 있는 세션이면 sessions/ 파일 작성
3. 고아 링크 확인: sessions/에서 참조한 [[개념]]이 concepts/에 없으면 만들거나 링크 제거
